# Publisher Resilience Assessment — 2026-10-24

Trigger: publishing stopped on 2026-10-23 17:43 UTC with eleven consecutive
`PUBLISHER_WRITE_ENTRY_UNAVAILABLE: reason=login_required_or_session_missing`
failures. The operator disabled the scheduler (`schedulerEnabled: false`).

Every number below was read from the production container
(`marketing-automation-app-1`) or its persisted data on 2026-10-24. Re-measure
before quoting them as current.

## F-01 The KE-004 fix was never deployed

- The container image was built **2026-09-06** and contains R1 and R2
  (`lib/scheduler/nextAttempt.ts` is present).
- The session fix `da49bdb` (2026-10-17) exists only on
  `fix/ppomppu-session-recovery`. `main` was last updated 2026-08-11 and is
  17 commits behind that branch.
- Proof: the error string `reason=login_required_or_session_missing` no longer
  exists in source. Current code emits `PUBLISHER_LOGIN_REQUIRED: reason=...` or
  `PUBLISHER_WRITE_ENTRY_UNAVAILABLE: reason=write_button_not_visible session=...`.
- Side effect: the old code saved cookies after a dead-session run. The
  storage-state mtime (03:21 UTC) matches the last failed run. An import made
  while a run was in flight would have been overwritten.
- Nothing on the dashboard shows which commit is running, so the gap stayed
  invisible for a week.

## F-02 The session has a ~7-day lifetime, and nothing anticipates it

| Event | UTC |
|-------|-----|
| Session imported (first success after KE-004) | 2026-10-16 15:43 |
| Last verified publish | 2026-10-23 17:11 (approx.) |
| First failure (`open-saved-drafts: no matching selector candidate`, i.e. logged-out write page) | 2026-10-23 17:27 |

- That is about 7 d 2 h under continuous hourly use, so the expiry is not an
  idle timeout. One data point; treat it as a hypothesis.
- `PHPSESSID` and `pmn` are both session cookies (`expires = -1`). No persistent
  login cookie exists in the saved state, even though the old scripted login
  ticked `auto_login`. Whether a human login with 로그인 유지 issues one is
  unverified.
- `cf_clearance` is valid until 2027-10-23 and is bound to the server IP.
- Recovery is manual (KE-004): export cookies from a browser, run
  `npm run session:import`, `docker cp`, `chown`. There is no expiry warning
  and no dead-session alert.

## F-03 A terminal failure is retried as if it were transient

- After the session died: 11 hourly attempts, each launching Chromium, running
  the observer, opening the board, capturing a failure screenshot and trace.
- The scheduler only knows `unexpected_error` and walks the 15/30/60 min ladder
  forever. It has no notion of "cannot succeed until a human acts".

## Rejected

- **Automated Turnstile solving** (solver services, stealth headed Chromium
  tuned to pass the challenge). It defeats the site's bot detection, raises the
  account's risk score with every attempt (KE-004 lessons), and likely breaches
  the site's terms. Session refresh stays human, made cheap and anticipated.
- **Switching content to workspace templates now.** Rejected because of F-05's
  last paragraph; replaced by a one-way online-to-workspace draft mirror (S3).
